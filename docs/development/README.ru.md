# Разработка Пульса URL

[English](README.md) · [Оглавление документации](../README.ru.md)

Веб-интерфейс и Electron поддерживают русский и английский. Модель SQLite, HTTP API и IPC описаны в архитектуре. Для правок интерфейса используйте руководство по переводу. [Архитектура и контракты](architecture.ru.md) · [Руководство по переводу](../localization/TRANSLATION_GUIDE.md) · [Как внести вклад](../../CONTRIBUTING.md#как-внести-вклад-в-пульс-url)

## Настройка и запуск

Установите Git и Node.js **24.x** с npm. Файл `.nvmrc` задаёт основную версию Node.js, CI использует Node.js 24.22.3. Выполните из корня репозитория.

```sh
npm ci
npm run dev
```

Откройте ссылку доступа из терминала. Vite отдаёт интерфейс на `http://127.0.0.1:5173` и направляет `/api` в Fastify на `127.0.0.1:8731`. Ключ из ссылки используется для открытия локальной сессии. Храните его приватно. После перезапуска сервера откройте актуальную ссылку.

```sh
npm run build
npm start         # Собранное веб-приложение на http://127.0.0.1:8731
npm run desktop   # Сборка и запуск Electron
```

`npm run build` проверяет типы, собирает React в `dist/client` и компилирует сервер, общие модули и точки входа Electron в `dist`. Веб-сервер раздаёт интерфейс и API на одном локальном адресе. Electron использует собственный протокол для собранного интерфейса.

### Локальные настройки

Веб-команды читают `.env`, если файл существует. Сделайте копию `.env.example`. `URL_PULSE_DB` меняет путь к `data/pulse.sqlite3`. В `PULSE_WEB_ACCESS_KEY` можно задать случайный постоянный ключ из 32–128 символов base64url. Новые сессионные данные создаются после каждого перезапуска. `SMTP_*` задаёт параметры почты, `PULSE_EMAIL_LOCALE` выбирает язык писем для всех проектов (`ru-RU` по умолчанию или `en-US`), `PULSE_REQUEST_SECRET_*` задаёт значения секретов HTTP-профилей. [Шаблон окружения](../../.env.example)

В Electron база `pulse.sqlite3` находится в пользовательском профиле. Для отдельного профиля задайте `PULSE_DESKTOP_DATA_DIR` в окружении запуска. SMTP и фоновая работа настраиваются через **Настройки приложения**. Язык писем сохраняется отдельно от параметров SMTP. При одновременном запуске веб-версии и Electron используйте разные базы. Каталоги данных должны принадлежать пользователю и иметь права `0700` на POSIX либо приватные ACL на Windows. Храните локальные настройки, секреты и базы вне Git.

Штатный профиль HTTPS использует корневые сертификаты среды выполнения. Для профиля `russian-ca` скачайте `Russian_Trusted_Root_CA.cer` отдельно. Используйте `cert/` в папке исходников для веб-версии и `cert/` в пользовательском профиле для Electron. Можно задать абсолютный путь через `PULSE_RUSSIAN_CA_FILE`. После изменения перезапустите приложение. Оно проверяет закреплённый отпечаток, срок действия, назначение CA и самоподпись. [Инструкция по CA](../user/README.md#российский-корневой-ca) · [TLS-профили](../../src/server/tls-profile.ts)

### Отладка

| Задача или симптом | Где проверить |
| --- | --- |
| Отладка React | Запустите `npm run dev`. Используйте инструменты разработчика и вкладку Network. |
| Отладка Fastify | Остановите текущий процесс сервера. Запустите `node --inspect --env-file-if-exists=.env --import tsx src/server/main.ts --dev`. При необходимости запустите Vite отдельно через `npm run dev:web`. |
| Порт занят | Освободите порт 5173 или 8731 для разработки, 8732 для сервера Playwright. |
| API возвращает 401 | Откройте свежую ссылку доступа из терминала по напечатанному локальному адресу. |
| SQLite уже открыта | Завершите владеющий процесс через Ctrl+C или **Выход** в Electron. Закрытие окна оставляет Electron в фоне. Сохраняйте `.owner-lock` рядом с базой. |
| `ERR_TLS_PROFILE_CA` | Проверьте путь и отпечаток файла. Используйте штатный профиль, если отдельный CA не нужен. |

Для статической проверки выполните `npm run typecheck`. Используйте стиль TypeScript и CSS окружающего кода. [Команды npm](../../package.json)

## Тестирование

| Команда | Что проверяет |
| --- | --- |
| `npm test` | Хранилище, контракты API, расписание, проверки, импорт, экспорт и вспомогательные модули Electron. |
| `npx playwright install chromium` | Устанавливает Chromium для браузерных тестов. |
| `npm run test:e2e` | Собирает приложение и запускает сценарии Playwright с тестовым сервером на порту 8732. |
| `npm run test:desktop` | Собирает и проверяет Electron на временном профиле. Нужен графический сеанс. |
| `node e2e/desktop-locale-smoke.mjs` | Проверяет выбор языка, нативные подписи, перезапуск и IPC после `npm run build`. |
| `npm run test:coverage` | Измеряет покрытие сервера, Electron и общих модулей. Отчёт в `coverage/node/`. Пороги 80% строк и 75% ветвей. |
| `npm run test:coverage:browser` | Измеряет покрытие React через Playwright. Отчёт в `coverage/browser/`. Пороги 84% строк и 79% ветвей. |

Для целевой проверки HTTP выполните `npm test -- tests/http-contracts.test.ts`. Чтобы проверить очередь и остановку, после сборки выполните `npx playwright test e2e/run-workflow.spec.ts`. `PULSE_E2E_BROWSER_CHANNEL=chrome` выбирает установленный Chrome. `PULSE_SMOKE_EXECUTABLE` указывает на исполняемый файл собранного Electron. Сценарии smoke используют временные профили и пропускают регистрацию протокола ссылок. [Проверка локализации](../localization/TEST_REPORT.md)

В тестах используйте синтетические данные, временную SQLite и локальные фикстуры. HTTP-контракты удобно проверять через `createApp()` и Fastify `inject()`. Закрывайте хранилища, воркеры и серверы перед очисткой временных файлов. [Тестовый сервер](../../e2e/server.ts) · [Electron smoke](../../e2e/desktop-smoke.mjs)

## Сборка установщиков

Для DMG требуется macOS с `ditto` и `hdiutil`. Windows x64 собирается на Windows с NSIS или на macOS с `makensis`. При нестандартном расположении компилятора укажите `PULSE_MAKENSIS`. Перед сборкой выполните `npm ci`.

```sh
# macOS
npm run make:mac -- --arch=arm64
npm run make:mac -- --arch=x64

# Windows x64
npm run make:windows
```

По умолчанию DMG сохраняется в `out/make/dmg/<arch>/Pulse URL-<version>-<arch>.dmg`, Windows EXE — в `out/installers/Pulse-URL-<version>-win-x64-Setup.exe`. Рядом находится `SHA256SUMS.txt`. Измените папку вывода через `PULSE_PACKAGE_OUT`. По умолчанию сборки тестовые, без подписи издателя. [Настройки Forge](../../forge.config.cjs) · [Скрипты упаковки](../../packaging/)

## Подготовка релиза

После согласования версии синхронизируйте `package.json`, `package-lock.json` и оба журнала изменений. Проверьте состав исходников и результаты тестов перед созданием тега на согласованном коммите. [Журнал изменений](../../CHANGELOG.md) · [Чеклист публикации](release-checklist.md#публикация-исходников)

Публичные релизы содержат архивы исходников. Локальные установщики и артефакты CI используются для проверок. Дополнительный российский CA скачивается отдельно. [Релизы GitHub](https://github.com/shanhaichik/URLPulse/releases)

При pull request, push в `main` или ручном запуске **Tests and coverage** собирает веб-версию и проверяет покрытие. **Desktop checks** запускает тесты, упаковку и smoke для macOS Apple Silicon, macOS Intel и Windows x64. Настольные задания запускают Vitest с двумя воркерами и лимитом 20 секунд на тест. Apple Silicon использует `macos-15`. [Tests and coverage](../../.github/workflows/tests.yml) · [Desktop checks](../../.github/workflows/desktop-build.yml)

Для **Source release** дождитесь успешных проверок на результате слияния PR в `main`. Создайте аннотированный тег `vX.Y.Z`, соответствующий `package.json`. Запустите workflow из основной ветки с этим тегом и `publish: false`. После приёмки запустите тот же workflow с `publish: true`. Он проверит тег повторно и создаст GitHub Release с архивами исходников и автоматически собранными заметками. [Source release](../../.github/workflows/source-release.yml)

Для будущих подписанных установщиков **Signed desktop release** использует защищённое окружение `desktop-release`, группу `pulse-signing` с нативными runners и точный SHA тега. Нужны сертификат и профиль нотарификации macOS, сертификат Windows и сервис меток времени. Workflow проверяет подписи, установка и удаление проверяются на Windows, а установщик, `SHA256SUMS.txt` и `release.json` загружаются для приёмки. Держите runners подписи отдельно от публичных PR. Перед распространением собранных файлов подготовьте сторонние уведомления об используемых компонентах. [Signed desktop release](../../.github/workflows/desktop-release.yml)
