# Проект архитектуры локализации

Базовые языки `ru-RU` и `en-US`. Русский используется по умолчанию и при повреждённом предпочтении. В web и Electron язык можно выбрать в верхней панели и в открытом диалоге. Меню Electron обеспечивает тот же выбор с клавиатуры и для закрытого окна через трей, где это поддерживается платформой.

## Варианты реализации

| Подход | Преимущество | Цена в URLPulse |
|---|---|---|
| **i18next и react-i18next, рекомендуемый** | Один механизм перевода для React, Fastify и main Electron. Работает синхронно с локальными ресурсами, поддерживает fallback и plural rules | Нужна типизация ключей, проверка каталогов и контроль размера сборки |
| Lingui с компиляцией каталогов | Удобное извлечение и стандартный ICU-синтаксис | Добавляет этап компиляции/извлечения в Vite и в `tsc` для Node и Electron. Потребуются изменения CI и процесса перевода |
| TypeScript и нативный Intl без библиотеки | Минимум новых зависимостей | Придётся поддерживать собственные правила выбора, интерполяции, диагностики каталогов и React-обновления |

Рекомендация учитывает два разных пути сборки в репозитории. [Множественные формы i18next](https://www.i18next.com/translation-function/plurals) · [Fallback i18next](https://www.i18next.com/principles/fallback) · [Lingui Core](https://lingui.dev/ref/core).

## Каталоги и состояние

- `src/shared/i18n/` содержит разрешённые локали, типизированные ключи, форматтеры и фабрику i18next. В каждом из 15 файлов `locales/*.ts` хранятся парные переводы по одному функциональному модулю. Оба языка входят в офлайн-сборку. Vite, Node и Electron импортируют каталоги своих поверхностей.
- React получает `I18nextProvider` до рендера корня. Язык хранится в отдельном ключе `localStorage` для web с обработкой ошибок доступа и синхронизацией через `storage`. При выборе обновляются `lang` и заголовок документа, сохраняются pathname, query, history, черновики, фокус, открытые диалоги и операции. Настройки языка и ключ локальной сессии независимы.
- Electron читает необязательную локаль из текущего файла настроек, проверяет её по allowlist, сериализует записи с другими настройками и сообщает о смене через ограниченный IPC. Сохранение только языка не должно расшифровывать или перезаписывать секреты SMTP. Main обновляет меню и трей без пересоздания окна. Нативный диалог использует снимок языка при открытии. Подписи, принадлежащие ОС, следуют языку ОС.
- Русский каталог используется при отсутствии непустого английского перевода. Для неизвестного ключа выводится общее сообщение. Vitest в CI показывает проблемный ключ и проверяет параметры, пустые строки и формы множественного числа. Форматтеры `Intl` кэшируются по локали. При первом запуске интерфейс русский.

## Ошибки, отчёты и фон

**Диагностика.** При запросе с заголовком `x-urlpulse-i18n: 1` известные ошибки API дополняются проверенными `messageKey` и `messageParams`. Клиент вычисляет перевод при выводе. Для исторических строк и асинхронных результатов адаптер распознаёт точные совпадения и шаблоны с проверяемыми параметрами. Остальные технические детали выводятся в исходном виде. SQLite и резервные копии сохраняют исходные строки.

**Экспорт.** Явный параметр `locale` в HTTP и IPC выбирает подписи Excel, статусы и известные диагностики. Интерфейс передаёт активную локаль. Вызов без локали сохраняет формат версии 1.5.1. Разделитель, BOM, порядок колонок, ISO 8601, экранирование формул и снимок данных сохраняются. CSV и JSON продолжают использовать стабильную схему. Локаль фиксируется при запуске выгрузки.

**Письма.** Согласован один язык на установку. В web это `PULSE_EMAIL_LOCALE` из окружения сервера. В Electron это отдельное поле активного локального профиля в настройках SMTP. При отправке worker берёт текущий язык установки один раз на письмо, в том числе при повторной доставке. Русский используется, если значение отсутствует или повреждено. Локаль писем не требует изменения базы и не зависит от языка окна.

**Безопасность.** Локаль выбирается только из встроенного перечня и не используется как путь, URL или имя файла для динамической загрузки. Подстановки рендерятся как текст React, текст SMTP передаётся plain text, экспорт использует существующее экранирование, а значения в логах и API сохраняют стабильные коды. Любые параметры, поступившие из API, проверяются перед интерполяцией. Добавление локали к IPC не расширяет список разрешённых сетевых действий.
