# Аудит скорости и UX Пульса URL 1.2.0

Замеры выполнены на одном Mac с Apple Silicon и macOS 26.5.2. Временная SQLite содержала 5 000 URL и 15 000 результатов. Сравнивались упакованные Electron 1.1.0 и 1.2.0. Отдельный прогон в Chromium проверял веб-интерфейс версии 1.2.0. Время внешних HTTP-запросов в замер не входило.

## Electron

Все значения в миллисекундах. p50 — медиана, p95 — 95-й перцентиль выборки.

| Сценарий | 1.1.0, p50 / p95 | 1.2.0, p50 / p95 |
|---|---:|---:|
| Открытие проекта до первой строки таблицы | 91,42 / 97,12 | 60,47 / 62,08 |
| Получение данных таблицы по IPC | 61,30 / 65,50 | 27,40 / 29,80 |
| Фоновый опрос без изменений по IPC | 61,30 / 65,50 | 0,20 / 0,40 |
| Поиск до обновления таблицы | 2,60 / 3,00 | 2,60 / 2,90 |
| Сортировка до обновления таблицы | 2,10 / 2,30 | 2,00 / 5,90 |
| Выделение всех 5 000 строк и снятие выделения | 1,50 / 1,80 | 1,30 / 2,60 |

Объём JSON таблицы по IPC сократился с 2 558 675 до 1 086 170 байт. Опрос при неизменной базе возвращает 18 байт. Убраны отдельные запросы к SQLite за последним результатом каждого адреса. Вычисления поиска и сортировки переиспользуются при действиях, которые не меняют таблицу или её фильтры.

В Chromium 1.2.0 медиана открытия — 42,10 мс. p95 поиска — 3,00 мс, сортировки — 2,10 мс, выделения — 1,50 мс.

## Качество интерфейса

- В DOM отображаются 25 строк на страницу, включая сценарий массового выделения 5 000 адресов.
- На ширине 390 px прокрутка остаётся внутри таблицы, без горизонтальной прокрутки всей страницы.
- Диалог добавления открывается клавишей Enter. Escape теперь закрывает диалог и возвращает фокус на кнопку, с которой он был открыт.
- Проверены подсказка Curator в отчёте, открытие адреса в браузере и очистка ленты через диалог подтверждения.
- В итоговом прогоне Electron и Chromium наблюдатель Long Tasks не зарегистрировал задач от 50 мс во время последовательности измеренных взаимодействий.

## Методика и границы

Измерены пять повторных открытий, 25 прогретых запросов IPC на сценарий и 20 действий каждого типа. Интервалы взаимодействий измерены внутри страницы от события до ожидаемого состояния DOM. Сценарии отделены друг от друга очередью событий. Это измерение обновления DOM, без фазы отрисовки и аппаратного ввода.

При изменениях во время активного запуска таблица получает компактный снимок проекта. Инкрементальные обновления отдельных строк не измерялись. Нативные замеры Windows, медленные устройства и полное измерение доступности интерфейса в этот аудит не входили.

Для повтора выполните `npm run audit:performance`. Для прогона упакованного Electron задайте `PULSE_BENCHMARK_DESKTOP` с путём к исполняемому файлу. Сценарий находится в [scripts/performance-audit.mjs](../scripts/performance-audit.mjs).
