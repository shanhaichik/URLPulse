# Как переводить Пульс URL

[English](TRANSLATION_GUIDE.en.md) · [Руководство разработчика](../development/README.ru.md)

Русский `ru-RU` используется при первом запуске и служит резервным языком. Английские тексты следуют нормам American English. Продуктовые термины собраны в [глоссарии](GLOSSARY.md).

## Добавить или изменить сообщение

1. Найдите каталог нужного экрана или слоя в `src/shared/i18n/locales/`. Для нового текста выберите стабильный ключ по назначению, например `deleteGroupWarning`.
2. Добавьте `ru` и `en` к одному ключу. При изменении существующего текста сохраните ключ и согласуйте переменные в обеих версиях.
3. В React создайте хук через `createMessages('groups', groupsMessages)` на уровне модуля. В компоненте вызовите хук и используйте `t('deleteGroupWarning', { name })`. Для Node.js и Electron используйте `createTranslator(locale, namespace, catalog)`.
4. Обновите соответствующее руководство или сценарий, если меняется подпись, которую читатель должен найти в интерфейсе.

Храните целое предложение в каталоге. i18next подставит `{{name}}` или другие именованные параметры с нужным порядком слов. Передавайте пользовательские данные как текст. Новые сообщения API для интерфейса добавляйте в диагностический каталог вместе с проверкой ключа и параметров, чтобы сообщение можно было перевести повторно после смены языка.

## Множественное число и форматирование

Для множественного числа передавайте числовой `count`. i18next использует правила `Intl.PluralRules` для каждой локали. Русскому нужны `one`, `few`, `many` и `other`, английскому — `one` и `other`.

Если число нужно отформатировать с разделителями или локальной десятичной запятой, передайте его вторым параметром, например `{ count, value: formatLocaleNumber(locale, count) }`, и используйте `{{value}}` в строках каталога. `count` выбирает форму.

```ts
checkedUrls: {
  ru: { one: 'Проверен {{count}} адрес', few: 'Проверено {{count}} адреса',
    many: 'Проверено {{count}} адресов', other: 'Проверено {{count}} адреса' },
  en: { one: '{{count}} URL checked', other: '{{count}} URLs checked' },
},
```

Для дат и чисел используйте `formatLocaleDate` и `formatLocaleNumber`. Идентификаторы, имена полей, коды ошибок, URL, значения фильтров, даты в ISO 8601 и введённые пользователем данные сохраняют свой исходный формат. Подписи Excel локализуются при выгрузке.

## Добавить язык

1. Добавьте IETF-тег в `supportedLocales`, словарный код в `languages` и резервное сообщение в `unavailable` в `src/shared/i18n/index.ts`. Расширьте `Catalog`, `isLocale` и проверку форм для нового языка.
2. Добавьте переводы в каталоги. Для множественного числа используйте набор `new Intl.PluralRules(locale).resolvedOptions().pluralCategories`.
3. Подключите самоназвание в переключателях React и нативном меню. Обновите локализацию Excel, переменную `PULSE_EMAIL_LOCALE`, настройки SMTP и тесты предпочтений. Язык установщика Windows настраивается отдельно в NSIS.
4. Прогоните переключение, сохранение, экспорт и почту для каждой локали. Добавьте её в матрицу визуальных проверок и пользовательские инструкции.

## Проверки

```bash
npm run typecheck
npm test -- tests/i18n-catalogs.test.ts tests/i18n-core.test.ts tests/i18n-diagnostics.test.ts tests/i18n-output.test.ts
npm run test:coverage:browser
npm run test:desktop
node e2e/desktop-locale-smoke.mjs
```

Проверка каталогов входит в обычный Vitest и запускается в CI. Она находит отсутствующие и пустые формы, расхождения параметров, ключи без найденных ссылок и текстовые литералы в React. Динамические семейства ключей учитываются по шаблону. Диагностика проверяется через реестр и тесты распознавания, поскольку её ключ приходит во время выполнения. Для текста, который собирается динамически, пройдите экран на обоих языках.
