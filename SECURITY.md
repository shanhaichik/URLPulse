# Security policy

[Русский](#политика-безопасности)

When the repository owner enables private vulnerability reporting, use the [GitHub private vulnerability report](https://github.com/shanhaichik/URLPulse/security/advisories/new). If the form is unavailable, keep details out of public issues, pull requests, and discussions while the owner configures a private channel.

Include the affected URLPulse version, operating system, run mode (browser or Electron), conditions needed to observe the issue, and its impact. Use synthetic data and remove credentials, tokens, private URLs, and personal information from any attachments.

Coordinate public disclosure with the maintainers through the private report so they can assess the issue and discuss a fix and the timing of an advisory.

Include the version you tested even if it is older. A maintained-version schedule has yet to be established.

## Политика безопасности

[English](#security-policy)

Когда владелец репозитория включит приватный приём сообщений об уязвимостях, используйте форму GitHub. Если форма недоступна, сохраните детали для приватного канала после его настройки владельцем. [Форма приватного сообщения](https://github.com/shanhaichik/URLPulse/security/advisories/new)

Укажите затронутую версию Пульса URL, ОС, режим запуска (браузер или Electron), условия воспроизведения и последствия. Используйте синтетические данные и удалите из вложений учётные данные, токены, приватные URL и личную информацию.

Согласуйте публичное раскрытие с сопровождающими проекта в приватном сообщении. Оно позволяет оценить уязвимость, обсудить исправление и сроки публикации.

Указывайте проверенную версию, в том числе более раннюю. График поддержки версий пока не установлен.
