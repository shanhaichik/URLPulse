# Корпоративный PAC и Basic — план реализации

> Для выполнения применяются Superpowers Executing Plans, Test-Driven Development и Verification Before Completion. Отметки ставятся после проверки.

**Цель.** Применять сценарий PAC проекта в прогонах, быстром импорте sitemap и потоковом каталоге. Разрешить корпоративным прокси работать по имени цели и принимать Basic через HTTPS.

**Архитектура.** Fastify, фоновые прогоны и Electron используют общий HTTPS-транспорт. SQLite хранит неизменяемую ревизию PAC с настройками прокси и ссылками на секреты. Каталог фиксирует её в транзакции создания задачи и читает пароль через основной процесс только при подключении к соответствующему прокси.

**Стек.** TypeScript, Node.js 24, React, SQLite, Fastify, Electron, Vitest и Playwright.

## Согласованный дизайн

- Доверенные прокси задаются для каждого проекта. Совпадение определяется нормализованными схемой, именем и портом. Для записи доступны разрешение частного IP прокси и выбор CONNECT по имени цели.
- Для частного адреса допускаются корпоративные диапазоны RFC 1918 и IPv6 ULA. Loopback, link-local и прочие специальные диапазоны блокируются. Цели по-прежнему проходят проверку публичной адресации в приложении. Прокси с CONNECT по имени дополнительно должен применять политику, ограничивающую соединения публичными целями.
- PAC вычисляется отдельно для перенаправлений и каждого удалённого sitemap. При проверке URL индивидуальный прямой выбор и фиксированный прокси HTTP-профиля имеют приоритет. Для PAC сохраняется явное правило DIRECT и действующие условия для перехода к резервному прокси.
- Basic доступен для HTTPS-прокси. TLS прокси и TLS цели проверяются независимо. Electron шифрует пароль через `safeStorage`, браузерный режим использует переменную `PULSE_REQUEST_SECRET_…`. Настройки и экспорт показывают только разрешённые метаданные. Недоступный секрет даёт ошибку настройки, `407` остаётся ответом прокси.
- Для ручного и планового прогона и каталога правила фиксируются при постановке в очередь, для быстрого импорта — при старте. При замене файла настройки доверия сохраняются, при отключении PAC снимаются с проекта. Прежние ссылки живут до завершения ссылающихся задач. Значение переменной среды задаётся владельцем установки.
- Приёмка использует контролируемые стенды web и Electron. Корпоративная проверка с реальным прокси относится к среде, где этот прокси доступен.

## Проверки на границах

1. HTTPS и HTTP с одинаковым именем и портом получают разную политику.
2. При смене прокси после сбоя пароль первого прокси не пересылается второму.
3. При замене PAC после очереди и после восстановления из паузы снимок остаётся доступным.
4. Несколько задач, использующих один секрет, освобождают его после последней ссылки. Старый пароль не отображается из API.
5. TLS к прокси проверяется отдельной парой сертификатов. Редирект на непубличную цель блокируется и для доверенного прокси.

## Ревью и проверка

- Ревью выявило зависимость TLS-имени прокси от заголовка CONNECT. Регрессионный сценарий проверяет отдельное имя прокси и ответ `407` на этом соединении.
- Ошибки предпросмотра IP-литералов, восстановления неканонических настроек и очистки последней версии воспроизведены падающими тестами и исправлены.
- Первый полный Vitest выявил зависимость теста блокировки SQLite от сборки мусора в дочернем процессе. Фикстура удерживает ссылку на владельца до выхода, проверка явно запускает сборку мусора. Диагностика проверила оба варианта при живом дочернем процессе.
- Итоговый Vitest с покрытием прошёл. 261 тест в 38 файлах, 92,25% строк и 83,33% ветвей.
- Итоговый Playwright прошёл в Chromium. 78 сценариев, включая добавление и удаление прокси на 390 px, фокус и смену языка с сохранением формы.
- Сборка на Node.js 24.22.3 прошла. Три сценария Electron прошли на Apple Silicon с одноразовыми профилями. Vite сообщает о JS-бандле больше 500 кБ без сжатия.
- Первый прогон PR #6 на macOS Intel превысил секундное ожидание запуска потока в тесте восстановления каталога. Локальный запуск с искусственной задержкой 1,3 секунды воспроизвёл состояние `queued`, после которого импорт завершился. Тесты запуска и восстановления потока используют общий лимит ожидания 8 секунд. [Первый прогон Intel](https://github.com/shanhaichik/URLPulse/actions/runs/45673568358/job/139415007653)
